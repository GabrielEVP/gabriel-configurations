# Sync Gabriel Configurations

## Activation Contract

Activate when the user says any variation of:
- "sync config" / "sincronizar configuraciones"
- "sync with the memory repo" / "sync con el repo de memoria"
- "actualizar gabriel-config" / "update gabriel-config"
- "subir cambios al repo de configuraciones"
- "gabriel-configurations"
- "sync todo" / "sync all"

This skill syncs ALL live config directories back to the GitHub repo:
`~/.config/opencode/`, `~/.config/ghostty/`, `~/.config/nvim/`,
`~/.config/zed/`, `~/.zshrc` (and zprofile/zshenv), `~/.config/zellij/`, `~/.tmux.conf`.

| Item | Reason |
|---|---|
| `node_modules/` | Runtime dependency |

| `.atl` | OpenCode internal state |
| `.gitignore` | Not versioned |

| `.git/` (anywhere) | Git internal |

## Hard Rules

1. **Never commit API tokens or secrets.** Before syncing, verify `opencode.json` does NOT contain real tokens — replace with placeholders if needed.
2. **Never delete files from the repo** that don't exist in live config — the repo may have template files that aren't in the live setup.
3. **Always check `git status`** before and after syncing.
4. **Always show the user a list of changes** before committing.
5. **Use conventional commits**: `feat(opencode):`, `fix(ghostty):`, `chore(nvim):`, etc.
6. **Always push** after committing unless the user says otherwise.
7. **Diff ALL directories** — run a full `diff -rq` for each, not just opencode.

## Execution Steps

1. **Pull latest**: `git pull --rebase` in repo to avoid conflicts.
2. **Diff everything**: Run `diff -rq` between each live config and repo counterpart, filtering out excluded paths.
3. **Categorize findings**: Identify new files, modified files, and files only in repo.
4. **Copy config files**: `rsync -a` for directories, `cp` for individual dotfiles.
5. **Verify**: Run `git status` and `git diff --stat`.
6. **Show user**: Present the categorized list of changes with Commit Confirmation protocol.
7. **Commit & push**: On user confirmation, `git add`, `git commit`, `git push`.
